## SPA delivery and query lifecycle

The SPA keeps route dispatch in `router.tsx`, shared explorer primitives in
`pages/pages.tsx`, and block, transaction, address, token/NFT, verification,
and entity dispatch in separate page modules. English and Chinese resources
are merged from matching domain modules, with Requests and Sourcify resources
loaded by their feature routes, preventing one language from silently acquiring
a different key layout. The pinned Oxlint and Oxfmt gates
are part of `web-lint`: TypeScript checking is followed by hooks, unused code,
classic cyclomatic complexity, function/file size, and formatting checks.
Transaction orchestration is separate from calldata, overview, logs, trace,
and secondary panels; contract proxy facts are separate from tab orchestration.
Wallet operation callbacks retain the same session fences in an internal Hook.
Generated API types remain generator-owned and are excluded from both tools.
Route components and feature-heavy editors/charts are lazy chunks; the initial
asset graph explicitly forbids page, ECharts, x402, verified-source, and
CodeMirror chunks. Hashed assets are built with Gzip/Brotli sidecars and a
SHA-256 size manifest. The embedded handler performs representation-aware
conditional delivery while keeping shell nonces, CSP, immutable caching,
HEAD, range, fallback, and reserved-path behavior intact. One durable
`/api/v1/events` EventSource marks ordinary browsing snapshots for explicit
refresh and updates the home/status allowlist; the home page
refetches one atomic `/api/v1/home` publication instead of opening a second
stream, and canonical lists no longer poll every two seconds. Home responses
carry `event_id`; clients pass their highest observed version as `min_event_id`.
A lagging API replica waits up to two seconds on its background feed before
returning `home_snapshot_unavailable`. Typed query metadata selects events, and
a closed EventSource recovers with one cursor-free connection and bounded
backoff as specified in [ADR-0004](../decisions/ADR-0004-durable-runtime-status-and-events.md).

Public query functions pass React Query cancellation signals to the HTTP client.
Cursor requests include the restart generation in their cache identity, so
recovery from an expired cursor obtains a fresh first page. Block-dependent
lists use the resolved block hash. Transaction decoding resources each retain
their own bounded identity-recovery state for the complete transaction identity.

- The SPA uses the public API for explorer data. Contract `eth_call` and
  `eth_sendTransaction` use only an injected wallet provider.

- Browser verified-ABI parsing normalizes historical Solidity field omissions
  and consistent `constant`/`payable` flags into one immutable modern ABI under
  [ADR-0013](../decisions/ADR-0013-embedded-spa-serving-and-browser-security.md#verified-abi-normalization).
  Explicit mutability conflicts, invalid entry shapes and resource-limit
  violations fail closed. Published artifacts and provenance are not rewritten.

- Explorer requests use operation functions generated by the pinned Hey API
  generator from OpenAPI. Every SDK call requires the project-owned Fetch client
  in `web/src/api/client.ts`; generated default clients are not imported by the
  application. The adapter fixes requests to same-origin `/api/v1`, preserves
  `no-store`/`same-origin` credentials, and owns browser `fetch`, error and envelope
  handling. EventSource retains its existing recovery lifecycle with a generated
  URL type; binary/CSV operations read the raw successful response body.

- Tailwind is compiled by its pinned Vite plugin into the content-hashed CSS
  asset. The existing base stylesheet remains authoritative, so Tailwind
  Preflight is intentionally omitted; theme-backed and responsive utilities
  implement shared layout primitives without a CDN or frontend runtime.

- The embedded file handler serves real files with `GET`/`HEAD`, but a missing
  route receives the SPA shell only for a non-reserved `GET` that accepts HTML.
  API, compatibility, operational, asset-shaped, malformed, HEAD, and mutating
  misses stay distinguishable. The index is `no-store`; exact Vite
  content-hashed assets are immutable with SHA-256 ETags. A `default-src
'none'` CSP explicitly permits only required same-origin resource types and
  forbids inline/evaluated script. Optional Turnstile adds only its fixed
  script/frame origin to shell responses when enabled; see
  [ADR-0013](../decisions/ADR-0013-embedded-spa-serving-and-browser-security.md).

## Private watchlists and bounded exports

[ADR-0051](../decisions/ADR-0051-watchlist-notifications-csv.md) owns SIWE-only
watch and notification resources plus the authenticated CSV response exception.
Writer transactions serialize per-user watch and browser-subscription limits and
bind enrollment to an exact canonical tip. Session-bound Web Push subscriptions
are private writer-owned state. A single maintenance sender per chain tails
first-canonical Core and first successful Token publications with volatile
cursors; startup and recovery discard backlog. Each candidate rechecks session,
watch, canonical block and exact publication, closes database state, then sends
once with TTL 0. No notification history, read state or retry queue exists.
Push transport pins checked DNS addresses and requires public HTTPS endpoints.
The default-off `push.unsafe_allow_private_networks` development option bypasses
only the public-IP restriction, allowing Fake-IP, private and loopback addresses.
HTTPS, TLS validation, redirect rejection, DNS bounds, IP pinning, timeouts and
response bounds remain unchanged in both all and split roles.

The SPA retains its public EventSource. Browser notifications use a same-origin
Service Worker and explicit permission/subscribe controls in Watchlist. Session
expiry, logout, revocation and disabled accounts stop new sends. The worker has
no offline cache; notification clicks open a validated transaction path.
CSV generation uses a single writer repeatable-read snapshot, verifies coverage,
checks all size/work limits, and closes that snapshot before returning bytes.
Admission and crash recovery are PostgreSQL facts, independent of API replicas.

## Optional browser human verification

Runtime `turnstile.enabled` is the single default-off switch for browser
verification, CSV exports and future Turnstile-protected operations. Actions
remain scenario-specific; adding an operation does not add a configuration
switch. Public config exposes only `enabled` and `site_key` while enabled and
omits the `turnstile` object while disabled. API/all read the secret from
environment or file. The HTTP layer validates
single-use tokens after session/Origin/CSRF and capability checks, before parsing
sources or opening export snapshots. Siteverify checks action and configured
hostname through fixed HTTPS with bounded time/response and no redirects or
retries. Failures are typed and redacted, with no readiness dependency. Browser
widgets are form-local, session-fenced and lazy; native API-key clients and
watch operations retain their existing paths. ADR-0013, ADR-0024 and ADR-0051
own the browser, verification and export contracts respectively.
